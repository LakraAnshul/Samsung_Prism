Guide Weave

An AI framework that turns appliance service manuals into illustrated, step-by-step repair guides — where every step is traceable to the page it came from.

International Institute of Information Technology, Naya Raipur
Samsung R&D Institute India · Bangalore

The brief

A service manual is not an answer

A technician with a dead washer has a question, not a document. Retrieval-augmented generation gets close — and then fails in ways that matter more in a repair guide than anywhere else.

Failure 01

Invented steps

A model handed evidence for steps 1, 2 and 5 will helpfully write steps 3 and 4. In a repair procedure that is not a fluent answer — it is a wrong one.

Failure 02

Wrong machine

Top-loader guidance confidently delivered for a front-loader. Semantic similarity does not respect model boundaries; nothing in a plain vector search enforces them.

Failure 03

Unanchored images

Diagrams retrieved by topic land next to the wrong step. The picture carries more instruction than the sentence, so a misplaced one misleads hardest.

What we built

Evidence in, verified guide out

Nine stages. The language model is one of them — and it is the only stage permitted to be creative, on a leash held by the two stages that follow it.

Determinism

Rebuildable from source

Document, problem, step and chunk IDs are derived from the file and its structure, not from a counter. The same PDFs rebuild the same index.

Scope carried forward

Metadata travels with the vector

Appliance type, brand, model and page number are stored on every point, which is what later makes a hard model filter possible instead of a hopeful one.

Stage 7A

Two searches, fused, then re-read

Dense search alone loses error codes. Sparse search alone loses paraphrase. We run both, fuse by rank rather than by score, and let a cross-encoder read the survivors.

Why rank fusion

Scores don't compare, ranks do

A cosine similarity of 0.81 and an IDF score of 14.2 have no common unit. RRF uses only the position each result took in its own list, so no weighting constant has to be tuned per query.

Why rerank at all

The first eight are what the model sees

Recall@8 was already 100% before reranking — the right chunk was in the pool. It was the ordering that was wrong, and the ordering is what survives into the prompt.

Correctness by construction

The system refuses to guess which machine

Model scope is resolved before retrieval runs, and the answer is one of three states — never a silent best effort.

The rule that does the work

A model filter is never dropped to find results

The common shortcut — widen the filter when a search returns too little — is exactly how cross-model contamination happens. Model-specific mode returns nothing rather than something from another machine.

0 contaminated chunks across the run

Honesty as a feature

Generic advice says so

For a machine we have not indexed, the system still helps — using generic Samsung washer evidence — but the prompt forbids the model from phrasing it as model-specific, and the response carries an explicit warning the UI renders.

The leash

Every claim is checked against the evidence

The model's output is treated as a proposal. Five checks run against the retrieved evidence before anything reaches the user, and each one deletes rather than repairs.

Validation rules

  1. 01Step must exist. A step ID absent from the evidence is dropped — this is what stops invented steps 3 and 4.
  2. 02Citation must belong to that step. A real chunk ID cited on the wrong step is a relational hallucination, and is rejected too.
  3. 03Image must belong to that step. Same rule for pictures. A real image on the wrong step is still wrong.
  4. 04Numbering comes from the source. Step numbers are realigned to the manual's own, not the model's count.
  5. 05Image data is re-hydrated. File paths from the model are discarded and replaced from the index — the model never supplies a path.

Where authority sits

The application decides, not the model

Model name, guidance scope, warnings and image URLs are written onto the response by the orchestrator after generation. Even a model that ignores every instruction cannot misreport which machine it answered for.

Prompt discipline

Ten absolute rules, temperature 0

Simplify wording, preserve meaning; warnings only from source text; declare insufficiency in a limitations field rather than filling the gap. JSON mode, with a two-attempt retry on rate limits and transient errors.

Retrieval

Did the right evidence surface?

Recall@8 and Recall@30, MRR and nDCG@8, matched on chunk ID. A separate contamination check confirms no chunk from another model entered the pool.

Answer

Did the guide keep the procedure?

Step recall and step order are computed deterministically on step IDs — no judge involved. Order is scored on the longest increasing run of matched steps.

Faithfulness

Is anything unsupported?

A separate Groq judge reads the generated guide against the source evidence and counts claims that the evidence does not support. Deterministic metrics are never delegated to it.

Reading the retrieval numbers

Perfect ranking on a single-model index

An MRR of 1.00 is a real result, but on one indexed machine and 150 well-separated problems it is close to the ceiling the corpus allows. It is evidence the pipeline is sound — not yet evidence it scales to a catalogue.

Scope of this run

The reported run evaluates a five-query sample across both configurations. The harness runs the full 450 unchanged; the sample is a cost decision, not a capability limit, and every figure here should be read with that denominator in mind.

The finding

Ordering, not recall, was the bottleneck

Recall@8 does not move — the evidence was always reachable. Everything downstream moves, because the model reads a better-ordered prompt. Faithfulness rising 15 points from a pure retrieval change is the clearest evidence of that.

The cost

+2.1 s of reranking, +10.7 s end to end

The reranker call itself is 2.1 seconds. The rest is a larger candidate pool and a longer prompt. At 34 seconds median, this is a correctness-first configuration and not yet an interactive one.

Latency is the open problem

Reproducibility

Runs are artefacts

Each benchmark run writes its own directory: the config it used, per-query records, aggregate summary, ablation table and a report. Nothing is overwritten, so two runs can always be compared.

determinism
temperature 0, fixed IDs
fallback
reranker failure degrades to RRF order
Failure behaviour When the reranker is unreachable the pipeline does not error — it falls back to the fused ordering, records the fallback and its reason in the trace, and returns a guide. The same applies to image retrieval: a step with no confident image renders without one rather than with a wrong one.

Known limitations

What we would not claim yet

Four things the numbers on the previous slides do not cover, stated plainly.

Limitation 01 · measurement bug

The safety metric reads the wrong field

Safety scores 0% — but the guides do carry warnings. The evaluator looks for a top-level safety_warnings list; the generator emits safety_warning per step. The metric never sees them. This is a scoring defect, not a system one, and the fix is known.

Fix identified, not yet applied

Limitation 02

34 seconds is not interactive

Median end-to-end latency is dominated by per-step image retrieval — one embedding call and one search per reconstructed step. Batching those into a single call is the obvious next move and is not yet done.

Architectural, addressable

Limitation 03

One machine is indexed

The three-state resolver and the generic fallback path are built for a catalogue, and are tested against one. Retrieval precision on a multi-model index — where near-identical procedures compete — is genuinely unmeasured.

Untested at scale

Limitation 04

Illustrations are rendered, not photographic

Step images are generated text cards, which is what makes the step-to-image link exact and complete. They convey the instruction; they do not show the part. Real diagrams from the manuals are the upgrade path.

By design, for now

Next

Where this goes from here

In priority order, and scoped so that each one is measurable against the harness that already exists.

  1. 01Repair the safety metric and re-run the full 450 queries. Aligns the evaluator with the generator's schema, and runs all 450 queries instead of five.
  2. 02Batch image retrieval into one call per guide. Removes the per-step embedding round trip — the path from 34 seconds toward single digits.
  3. 03Index a second and third washer model. Turns model scoping from a design argument into a measured one.
  4. 04Extract real diagrams from the manuals. Replaces rendered cards with real figures, reusing the same step linking.
